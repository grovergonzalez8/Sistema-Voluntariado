# Política de prompts

## Antes de registrar

1. Eliminar secretos, tokens, URLs privadas y datos personales.
2. Separar requisitos confirmados de hipótesis.
3. Definir alcance, exclusiones, permisos y acciones destructivas prohibidas.
4. Indicar verificaciones y formato de evidencia.

## Revisión

- Una persona revisa el prompt y el diff resultante.
- Cambios de seguridad, datos o arquitectura reciben revisión especializada.
- Prompts operativos no alteran ADRs ni instrucciones persistentes de forma implícita.
- Un prompt desactualizado se conserva como registro histórico y se crea una versión nueva.

## Formato futuro

Fecha, objetivo, autor/herramienta, contexto no sensible, prompt, resultado, archivos, validaciones, commits, decisiones y revisión humana.
